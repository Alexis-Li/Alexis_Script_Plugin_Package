# {{PROJECT_NAME}} 开发线路

本文档规定**先做什么、后做什么、每个阶段做到什么算通过**。

- 近期的阶段写到任务一级（`S<阶段>-T<n>`）。更远的阶段只写目的、范围和
  验收标准，任务在该阶段开始时根据当时的实际情况拆分，写进它的总工单。
- 阶段对应一个总工单，任务对应它下辖的子工单（见 [workflow.md](workflow.md)
  第 4.1 节）。
- 任务之间按依赖关系进行，没有依赖的可以并行。任务说明中的文件名、命令名
  是建议，实现时可以调整。
- 阶段完成的含义：验收标准满足，用户做出"继续"的决定。
- 当前进行到哪里，见各阶段的总工单。
- 计划变化时在原处改写本文档。
- 任务按实验方式进行的，在条目中标明"实验任务"，遵守 workflow.md 第 6.1 节。

## 如果某个阶段走不通

验收不通过时，按以下顺序处理，并把结论写在阶段总 Issue 中：

1. 分清问题出在流程的哪一步。用该步骤的中间结果和检查的指标来判断，不靠猜。
2. 问题在某一步内部：换该步骤的做法（workflow.md 第 6.2 节）。架构保证其他
   步骤不受影响。
3. 问题在步骤之间的数据定义：按 workflow.md "架构变更"（第 8 节）处理，
   改 architecture.md 之后再动代码。
4. 连续两轮改进后验收仍不通过：停下来，向用户说明现状、原因和可选的
   方向，由用户决定继续、缩小范围或停止。
