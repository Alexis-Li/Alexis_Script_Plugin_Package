## 编号

| 前缀 | 含义 |
| --- | --- |
| `G-` | 目标：要达到什么效果 |
| `NG-` | 非目标：明确不做的事 |
| `F-` | 功能：用户能做什么、结果是什么 |
| `Q-` | 质量要求：确定性、性能、稳健、平台等可检查的指标 |

项目有明确的输入和输出格式时，另加 `IN-`（输入）和 `OUT-`（输出）。
编号一经分配不再改作他用；条目被删除后，它的编号作废。Issue、测试和审核
按编号引用，不复述条目。

## 8. 验收方式

验收分三层。前两层每项功能都要通过；第三层在阶段验收和标明需要用户的
任务中进行：

1. **自动测试。** 用程序生成的标准数据验证行为，不依赖用户的生产素材。
2. **样本基准。** 在用户提供的样本上运行，得到检查结果和指标，并与手工做法
   对比。
3. **目视验收。** 用户打开结果查看，判断它实际好不好用，并指出自动检查
   没有覆盖到的问题。评语按 [workflow.md](workflow.md) 处理。
