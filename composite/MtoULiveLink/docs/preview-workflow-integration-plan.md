# 三项原型接入 MtoU 主流程的整合方案

状态：**方案草案，尚未实施**。2026-10-13 根据 #47 汇总验收准备。
本轮授权仅包含验收和方案准备；以下工作应在后续实施会话启动。
本文的推荐选择不是已生效的协议、ADR、支持承诺或产品验收结论。

## 目标与交付边界

在现有 MtoU 双端入口完成一条连续工作流：选择 UE 场景参考范围与共同摆放，
配对 Maya 动画对象和 UE 目标，在 UE 的镜头／Sequencer 时间下检查 Maya
已求值的角色与独立道具／副角色，退出后恢复原控制。保留已验收的单角色
实时、缓存和服装比较工作流，以及既有动画导出、导入和 Sequencer 组装流程。

首个整合版本建议支持一个主角色和至多一个独立骨骼对象；单角色是同一流程的
退化情形。两个独立对象分别协商，Additional Parts 仍表示同一角色的组成。
新联动先用于 Animation preview；单角色 Model preview 及服装比较保持原有
入口，多角色 Model preview 不由本方案自动承诺。

三个原型的共同接口先统一设计，再按用户流程实施，不能把三套独立端口、
样例脚本和控制按钮直接并列交给用户。首版整合不实现多对象缓存或
Sequencer 驱动缓存；已有单角色缓存继续可用。两者的后续扩展边界见下文。

## 推荐的共同契约

### 空间：沿用产品坐标，统一摆放

采用当前角色、道具和默认 FBX 参考共有的厘米映射：
`C(x,y,z) = (x,z,y)`。调整相机适配到这一空间，避免改变已有制作物和动画路径。
#52 的 UE→Maya `(y,z,-x)` 只保留为历史原型约定。

设 `A` 为一组预览对象共有的 UE 放置变换，首版仅允许静态平移＋旋转、单位缩放。
下面使用列向量表示**世界点**，不是 Maya／UE API 的矩阵存储顺序：

```text
Maya 动画世界点 → UE：u = A · C · m
UE 相机／参考世界点 → Maya：m = C⁻¹ · A⁻¹ · u
```

`A=Identity` 对应现有原点流程。非原点场景通过同一个 A 对齐；首版不再另设
相机原点、参考原点或按对象自动吸附。A 不应从采样 root 姿势推导。
对象自身相对位置与引用父级运动已经包含在 Maya root world pose 中，不能再次
加到 UE Actor／socket。移动 socket、动态 Anchor、负缩放／非均匀 Anchor
首版明确拒绝；几何对象自身的非均匀缩放继续按 #53 测量路径保留。

相机朝向须按映射后的 right/up/forward 基向量适配 Maya 相机局部轴；几何
继续保留已测的 FBX node-frame factor；骨骼继续使用 bind→target-reference
投影。不能把世界点公式机械地应用于相机 Euler、FBX 节点矩阵或骨骼局部姿势。
Actor／组件如何表达 A 要由联合世界 oracle 验证，不能另加“修正 root 旋转”。

新增 `space_revision` 同时绑定 A、单位和映射。修改 A 先结束当前预览，重新
对参考容器应用明确变换／验证，再建立新会话；相机、对象和参考版本不一致时
不得进入镜头联动。容器只保存同一转换的结果，不给每个模型重新归零。

### 时间：三个互斥控制状态

| 状态 | 时间控制方 | 允许操作与转换条件 |
| --- | --- | --- |
| 实时预览 | Maya | Maya 播放／拖动／编辑；UE 可显示效果。进入镜头联动时停止 Maya 自主播放并取得控制权。 |
| 缓存预览 | UE Cached Playback 单调时钟 | 沿用 Ready、播放、暂停、定位、循环与播放段语义。首版只允许单角色；进入镜头联动前显式退出并收到清除确认。 |
| 镜头联动 | UE 当前 Level Sequence | UE 拖动、播放、cuts；Maya 跟随时间并回传完整姿势。Maya 不能反向控制时间；可在暂停帧编辑绑定并回传新求值结果。 |

相机传递也由镜头联动状态拥有，首版不增加第四个独立时钟模式。切换采用
“停止旧驱动／等待确认 → 验证新输入 → 取得新控制权”；失败回到明确的安全
状态并恢复原驱动，不同时启动两个控制方。退出镜头联动恢复进入前的 Maya
时间、相机／门和 UE 目标驱动，保留恢复结果及失败原因；不会自动恢复旧缓存播放。

时间采用明确的 UE tick/display rate、Maya fps 与两端起始帧：
`maya_time = maya_origin + (ue_display_frame - ue_origin) * maya_fps / ue_display_rate`。
帧率使用有理数，不向整数取整；沿用 #52 的 cuts／一层子序列范围和 1/1000 tick
身份精度。改变序列、时间映射或相机内容产生新求值目标。

镜头联动允许淘汰未完成的旧实时目标，持续播放时显示“等待／跟随滞后”及最后
完整应用时间，不能宣称每个渲染帧均同步。UE 停止拖动／播放后必须在有界时间内
收敛到最新目标。严格逐帧、不静默丢帧仍由 Cached Playback 承担；不修改
[ADR 0013](adr/0013-upload-the-cache-before-local-replay.md) 来掩盖联动延迟。

### 身份：会话、对象集合与求值目标分开

推荐一个双向控制会话，以明确的 `object_id → Maya root → UE target` 表连接：

- `session_id` 隔离连接；`set_revision` 隔离参与对象的集合；各对象另有输入修订。
- `object_id` 在当前配置生命周期稳定，不用骨骼短名、数组顺序或 UI 显示名路由。
  目标必须显式选择且不重复；full-body／arms 替换须重新协商。
- `space_revision` 和时间映射修订参与 Ready 与 frame 校验。
- UE 的 `eval_id` 表示时间＋cut＋相机内容；`transport_serial` 只表示发送次序。
  Maya 的 `sample_serial` 表示同一目标下新采样的姿势，允许停帧修改产生新结果。
- 一次回传覆盖当前集合的完整对象姿势／Morph，以及 camera/time 的实际回读状态。
  Maya 在主线程设时间、等待求值并采样所有根；只有 UE 当前目标的完整回传可提交。
  心跳不淘汰同一目标的在途结果；旧会话、旧集合、旧空间、旧目标和重复采样均拒绝。

UE 先验证全组，再在一个 game-thread 更新中安排所有对象显示；在实际组件求值
完成后记录应用证据。任一对象失败时保持上一组完整结果并显示失配，不让两个
对象显示不同源时间。仅完成多次 Live Link publish 不构成原子显示证明。

显式移除副对象时先停止接收旧集合、恢复该对象、提升集合修订并确认，再继续
主对象；公共 TCP 失联则结束整组。输入、骨架、绑定目标改变采用结束／重新
协商路径，不热替换静态骨骼数据。主角色的 Generated、Driver 和 Additional
Parts 继续共享该对象的协商与 Morph 集合，不各自变成 Subject。

### 驱动与资源：持有期间独占，退出可核对

每个目标先枚举实际 writer 并保存动画状态，明确停用相关动画／Sequencer 写入，
再取得预览控制。Sequencer 时间和无关轨道继续运行；原 Sequence、Anim Blueprint、
Binding、骨骼资产不保存改写。未知 writer、移动 socket 或无法恢复的目标写前拒绝。
无原驱动的对象退出后明确回到参考姿势，不能残留最后一帧。

首版只创建工具拥有的临时 Maya 相机，不借用制作相机；门和 undo 状态先检查
可写并保存，退出／失败恢复。参考几何为独立、可重复更新的容器快照，断开连接
不自动删除，用户可显式移除；不加入工作配置记忆或后台自动更新。

场景参考继续使用“常驻关卡＋显式已加载子关卡”、不自动加载、不改成 Actor
选择。保留支持／跳过／不完整报告。交付文件和 FBX 内容两处检查图片数据，
允许材质分配和外部路径引用，默认灰模。产品入口不暴露诊断绕过开关。
保留暂存、验证、替换、回滚边界；不把原型 `--dry-run` 标成无副作用预览。
产品的范围／规模预检应只读；实际导入和恢复需明确执行。

更新前核对整个工具容器的节点所有权，发现外来或无法分类节点即拒绝替换／删除；
不能把原型只覆盖顶层 transform 的证据宣传为任意深层节点安全。失败要保留
旧参考和残留定位信息，让用户能够恢复。

## 保留给后续规格的扩展

- **多对象缓存：** 按集合冻结同一范围／fps／采样点，原子 Ready、原子应用，任何
  对象上传或修订失败使整组失效；随后修订 ADR 0013 的 segment／complete 语义。
  在这项实施前，多对象配置禁用捕获入口并说明原因；返回单角色后原缓存流程可用。
- **Sequencer 控制缓存：** 另定义外部时钟、抽样／插值、跳转和完成证据；不复用
