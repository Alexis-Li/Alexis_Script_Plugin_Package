# 三项原型接入 MtoU 主流程的整合方案

状态：**已由 #56／#57 承接并进入实施**。2026-10-13 复核 #56 的范围、源码和原型证据；
2026-10-14 起按 [I-1（#57）](https://github.com/Alexis-Li/Alexis_Script_Plugin_Package/issues/57)
实施单角色接入。本文保留空间、时间、身份、驱动所有权与资源恢复的设计依据；
已实施部分以 `protocol/v10.md`、[ADR 0014](../adr/0014-one-time-authority-and-staged-pose-groups.md)
和实际源码为准，本文的推荐措辞不再覆盖这些生效结论。

推荐方向：**一个产品会话、一套空间约定、互斥时间控制、整组姿势提交**。
先完成单角色在真实镜头下的正式路径，再扩为双对象，最后完成持续播放和交付
验收。优先验证持续播放是否能前进、目标能否安全接管和整组能否一致显示；
这些结果决定实现方案，不能等 UI 接完后再验证。

## 目标与交付边界

在现有 MtoU 双端入口完成一条连续工作流：选择 UE 场景参考范围与共同摆放，
配对 Maya 动画对象和 UE 目标，在 UE 的镜头／Sequencer 时间下检查 Maya
已求值的角色与独立道具／副角色，退出后恢复原控制。保留已验收的单角色
实时、缓存和服装比较工作流，以及既有动画导出、导入和 Sequencer 组装流程。

首个整合版本建议支持一个主角色和至多一个独立骨骼对象；单角色是同一流程的
退化情形。两个独立对象分别协商，Additional Parts 仍表示同一角色的组成。
新联动先用于 Animation preview；单角色 Model preview 及服装比较保持原有
入口，多角色 Model preview 不由本方案自动承诺。

三个原型的共同接口先统一设计，再按用户流程实施，不能把三套独立端口、
样例脚本和控制按钮直接并列交给用户。首版整合不实现多对象缓存或
Sequencer 驱动缓存；已有单角色缓存继续可用。两者的后续扩展边界见下文。

## 推荐的共同契约

### 空间：沿用产品坐标，统一摆放

采用当前角色、道具和默认 FBX 参考共有的厘米映射：
`C(x,y,z) = (x,z,y)`。调整相机适配到这一空间，避免改变已有制作物和动画路径。
#52 的 UE→Maya `(y,z,-x)` 只保留为历史原型约定。

设 `A` 为一组预览对象共有的 UE 放置变换，首版仅允许静态平移＋旋转、单位缩放。
下面使用列向量表示**世界点**，不是 Maya／UE API 的矩阵存储顺序：

```text
Maya 动画世界点 → UE：u = A · C · m
UE 相机／参考世界点 → Maya：m = C⁻¹ · A⁻¹ · u
```

`A=Identity` 对应现有原点流程。非原点场景通过同一个 A 对齐；首版不再另设
相机原点、参考原点或按对象自动吸附。A 不应从采样 root 姿势推导。
对象自身相对位置与引用父级运动已经包含在 Maya root world pose 中，不能再次
加到 UE Actor／socket。移动 socket、动态 Anchor、负缩放／非均匀 Anchor
首版明确拒绝；几何对象自身的非均匀缩放继续按 #53 测量路径保留。

相机朝向须按映射后的 right/up/forward 基向量适配 Maya 相机局部轴；几何
继续保留已测的 FBX node-frame factor；骨骼继续使用 bind→target-reference
投影。不能把世界点公式机械地应用于相机 Euler、FBX 节点矩阵或骨骼局部姿势。
Actor／组件如何表达 A 要由联合世界 oracle 验证，不能另加“修正 root 旋转”。

新增 `space_revision` 同时绑定 A、单位和映射。修改 A 先结束当前预览，重新
对参考容器应用明确变换／验证，再建立新会话；相机、对象和参考版本不一致时
不得进入镜头联动。容器只保存同一转换的结果，不给每个模型重新归零。
旧参考可保留供恢复，但标为旧修订，不能仅改版本号便当作新空间的参考。
更新参考、改变 A 或时间映射均在结束预览后执行；普通单角色实时／缓存不以
安装场景参考为前提。镜头联动必须明确参考为当前修订或用户显式选择无参考。

### 时间：三个互斥控制状态

| 状态 | 时间控制方 | 允许操作与转换条件 |
| --- | --- | --- |
| 实时预览 | Maya | Maya 播放／拖动／编辑；UE 可显示效果。进入镜头联动时停止 Maya 自主播放并取得控制权。 |
| 缓存预览 | UE Cached Playback 单调时钟 | 沿用 Ready、播放、暂停、定位、循环与播放段语义。首版只允许单角色；进入镜头联动前显式退出并收到清除确认。 |
| 镜头联动 | UE 当前 Level Sequence | UE 拖动、播放、cuts；Maya 跟随时间并回传完整姿势。Maya 不能反向控制时间；可在暂停帧编辑绑定并回传新求值结果。 |

相机传递也由镜头联动状态拥有，首版不增加第四个独立时钟模式。切换采用
“停止旧驱动／等待确认 → 验证新输入 → 取得新控制权”；失败回到明确的安全
状态，不同时启动两个控制方。Disconnected、Transitioning、Recovering 是生命周期
状态，不是额外时间控制方；转换期间禁止新姿势提交，UI 不预报已成功。

| 操作 | 成功后 | 失败及恢复 |
| --- | --- | --- |
| 实时 → 镜头联动 | 保存 Maya 时间、播放与视图状态，停止 Maya 自主播放，检查序列／相机／目标接管；双方确认新的 mode_revision 后由 UE 驱动。 | 写前失败保留实时；接管中失败撤回已取得资源。恢复完整且旧会话仍有效才回实时，否则结束会话并报告恢复缺口。 |
| 缓存 → 镜头联动 | 按现有 clear_id 等待匹配的 cache_cleared，再执行进入联动。 | 清除超时不能进入新模式；清除已成功后不得自动复活旧缓存。清楚报告现在是实时、断开还是恢复待处理。 |
| 镜头联动 → 返回实时 | 取消联动目标，恢复进入联动前的 Maya 时间、视图／门，保持 Maya 暂停；UE 目标继续由 MtoU 接管，新 revision 下采集实时姿势。 | 无法恢复则结束会话，不在两个 writer 都启用时宣称已返回实时。用户主动恢复 Maya 播放。 |
| 结束预览／断连／宿主销毁 | 先关提交闸门，再释放所有预览接管；恢复 Maya 状态和 UE 原 writer。原 Sequence 按当前时间重新求值，无 writer 时回参考姿势。 | 恢复尝试必须幂等、逐资源记录；保留失败原因与残留定位，禁止自动重新连接。 |

结束联动不倒拨 UE Sequence，不自动开始旧缓存；工具曾暂停的其他驱动只在
句柄仍有效且原控制关系未改变时恢复其原状态。故障不能用“断开成功”掩盖恢复失败。

时间采用明确的 UE tick/display rate、Maya fps 与两端起始帧：
`maya_time = maya_origin + (ue_display_frame - ue_origin) * maya_fps / ue_display_rate`。
帧率使用有理数，不向整数取整；`ue_display_frame` 固定指根 Level Sequence 的
时间，子序列局部时间由 UE 求值解析，不再额外加一次偏移。沿用 #52 的 cuts／
一层子序列范围和 1/1000 tick 身份精度。序列、cut 实例、相机内容和时间映射
参与目标身份；返回同一帧不等于重用旧目标，传输序号不代替求值身份。

推荐调度保留三个独立位置：`desired` 是 UE 最新希望看到的目标，`issued` 是已
发给 Maya 的目标，`applied` 是 UE 实际完整显示的结果。至多一个 issued 和一个
可覆盖的 pending desired；心跳不创建新目标。连续播放／拖动只合并尚未发出的
目标，不因 desired 又前进一帧就取消 issued。有效 issued 的完整结果可以提交，
但落后于 desired 时只能显示“跟随滞后”，不能标为当前镜头同步。成功后发出最新
desired，不补发整个历史队列。该策略是产品候选，未改动 #52 的历史验收约定。

暂停、cut、相机配置／停帧内容编辑以及显式不连续跳转令旧 issued 失效；随连续
时间正常变化的相机变换不触发取消。记录取消身份，清掉
旧 pending，优先处理最后目标。Maya 已在进行的宿主求值不能假定可中断：等其
返回后丢弃旧结果再采最新目标，网络线程不能强行操作 Maya。重复暂停通知和
心跳不得反复取消同一目标。长期无完整结果转为超时，不能无限显示“同步中”。

播放中 UE 镜头仍按 Sequencer 前进，Maya 临时相机和整组姿势关联 issued 目标；
这不承诺当下 UE 镜头与滞后姿势同帧。UI 同时显示目标时间、最后应用时间及延迟。
UE 停止拖动／播放后必须在有界时间内收敛到最新目标，才可显示“已同步”。
严格逐帧、不静默丢帧仍由 Cached Playback 承担；不修改
[ADR 0013](adr/0013-upload-the-cache-before-local-replay.md) 来掩盖联动延迟。

### 身份：会话、对象集合与求值目标分开

推荐一个双向控制会话，以明确的 `object_id → Maya root → UE target` 表连接：

- `session_id` 隔离连接；`set_revision` 隔离参与对象的集合；`mode_revision` 隔离
  同一连接内的时间控制转换；各对象另有输入修订。
- `object_id` 在当前配置生命周期稳定，不用骨骼短名、数组顺序或 UI 显示名路由。
  目标必须显式选择且不重复；full-body／arms 替换须重新协商。
- `space_revision` 和 `time_mapping_revision` 参与 Ready 与 frame 校验。
  UE 提供会话内有效的目标句柄（world／Actor／component 身份及代数），Maya 显式
  配对本场景根节点；对象销毁／换场景后同名路径不能继承旧句柄。
- UE 的 `eval_id` 表示时间＋cut＋相机内容；`transport_serial` 只表示发送次序。
  Maya 的 `sample_serial` 表示同一目标下新采样的姿势，允许停帧修改产生新结果。
- 一次回传覆盖当前集合的完整对象姿势／Morph，以及 camera/time 的实际回读状态。
  Maya 在主线程设时间、等待求值并采样所有根；只有未取消 issued 的完整回传可提交。
  心跳不淘汰同一目标的在途结果；旧会话、旧集合、旧空间、旧模式、已取消目标和
  重复采样均拒绝。停帧修改产生递增 sample_serial；一组对象不能混用多个 serial。
  Ready、模式／移除确认和 applied 均回显所需身份，不能只验证入站 frame。

UE 先验证全组，再在一个 game-thread 更新中安排所有对象显示；在实际组件求值
完成后记录应用证据。任一对象失败时保持上一组完整结果并显示失配，不让两个
对象显示不同源时间。仅完成多次 Live Link publish 不构成原子显示证明。
实现应暂存完整、不可变的 frame group，把骨骼、Morph 和各 Additional Part 的
消费绑定到同一个提交代数；完成屏障前不能提前确认 applied。预检失败时不写，
提交中失效则保留／恢复上一完整组或结束整组并恢复原 writer，不能带着半组继续。
先验证现有 Anim/retarget 路径能否做到这一点，再决定内部同步方式；不把原型的
直接写组件路径无条件替代产品 Live Link、缓存和 Model 路径。

显式移除副对象时先停止接收旧集合、恢复该对象、提升集合修订并确认，再继续
主对象；公共 TCP 失联则结束整组。输入、骨架、绑定目标改变采用结束／重新
协商路径，不热替换静态骨骼数据。主角色的 Generated、Driver 和 Additional
Parts 继续共享该对象的协商与 Morph 集合，不各自变成 Subject。
首版将上述输入变更、增加对象及移除主角色统一为结束整组后重新连接；只有
显式移除副对象允许在原连接内重建集合。移除恢复失败则结束整组并保留恢复记录，
不提交新集合 Ready。这样先保留 ADR 0002 的保守失效边界，避免实现局部热更新。

### 驱动与资源：持有期间独占，退出可核对

每个目标先枚举实际 writer 并保存动画状态，明确停用相关动画／Sequencer 写入，
再取得预览控制。Sequencer 时间和无关轨道继续运行；原 Sequence、Anim Blueprint、
Binding、骨骼资产不保存改写。未知 writer、移动 socket 或无法恢复的目标写前拒绝。
无原驱动的对象退出后明确回到参考姿势，不能残留最后一帧。

现有 Binding Actor 是默认产品入口；配对还须明确最终显示的组件，不能靠扫描
世界内唯一 Actor 或复制一个临时 Actor 来声称接管了既有 Sequence 的目标。
I-1 的早期验证须明确已有 Sequence 的实际绑定能否由该入口解析；若需要支持
外部 SkeletalMeshComponent，以 Editor 目标适配器实现 Animation preview 接管，
复用同一严格协商，不把任意 Actor 支持隐含为已完成。该目标类型在 I-1 关口固定。

writer 清单至少区分动画实例／单节点、骨骼与 Transform 轨道、Control Rig、
Post Process、物理／布料和父级驱动，并记录支持、明确停用或拒绝。这是检查清单，
不是首版全支持承诺。对于共享轨道、动态 spawnable、多个活动 Sequencer 等无法
隔离的目标，先写前拒绝并指出具体来源；不能暂停驱动相机的整个 Sequence 来
替代逐目标接管。生产验收必须使用已有资产的一次性场景副本、保留所需依赖，
检查自然 tick 下实际 writer 与恢复姿势、包 dirty 状态及资产未保存改写。

首版只创建工具拥有的临时 Maya 相机，不借用制作相机；门和 undo 状态先检查
可写并保存，退出／失败恢复。参考几何为独立、可重复更新的容器快照，断开连接
不自动删除，用户可显式移除；不加入工作配置记忆或后台自动更新。
用户选定的 modelPanel、原 look-through 相机与可写分辨率门都纳入恢复；临时
相机不进入动画交付。视图不存在、门被锁定／驱动时写前拒绝并说明处理动作。
输出宽高与像素长宽比由 UE 入口显式设置并显示来源，变化产生新相机目标；
首版不猜测 MRQ，画面一致验收只在记录的相同输出门下成立。

场景参考继续使用“常驻关卡＋显式已加载子关卡”、不自动加载、不改成 Actor
选择。保留支持／跳过／不完整报告。交付文件和 FBX 内容两处检查图片数据，
允许材质分配和外部路径引用，默认灰模。产品入口不暴露诊断绕过开关。
保留暂存、验证、替换、回滚边界；不把原型 `--dry-run` 标成无副作用预览。
产品的范围／规模预检应只读；实际导入和恢复需明确执行。

更新前核对整个工具容器的节点所有权，发现外来或无法分类节点即拒绝替换／删除；
不能把原型只覆盖顶层 transform 的证据宣传为任意深层节点安全。失败要保留
旧参考和残留定位信息，让用户能够恢复。
文件交接拥有独立 transfer_id、内容摘要、范围及 space_revision；只接受已完成
导出的本机交接目录，验证后再导入。生产资产目录不是临时工作区。导出方清理
已确认不再使用的交接文件，Maya 管理参考容器；取消、重试和清理只操作明确归属
的资源。对陈旧 manifest、摘要不符、超预算、图片数据与外来节点均先拒绝，
失败不销毁旧参考，不把断开会话等同于删掉用户保留的参考。

handoff，控制消息只交换版本、摘要、路径和结果。不能把大 FBX 塞进姿势队列。
双方独立部署，不运行 sibling host 目录代码，也不依赖安装三个 Prototype 插件。

双端成对升级；不匹配版本给出更新原因，不静默解释为旧 v9。保留原单角色操作、
资产序列化及恢复行为。若后续要求旧 v9 客户端兼容，应另定适配和测试范围。
新版本号、依赖与包内容在实施票确定，本方案不改当前 0.9.0／v9。

协议第一份 corpus 须覆盖：协商能力／整组 Ready、模式切换及失败、相机时间请求、
完整姿势结果／实际 applied、停帧再采样、心跳、移除确认、结束与恢复结果；同时
覆盖非有限数、错误长度／重复 ID、过期身份、部分集合、断包／超大消息和超预算。
新实时 frame group 的候选编码上限沿用产品单消息 32 MiB，但按**整组**计量，
不是每对象各取 32 MiB；解析后内存、控制队列长度、超时和场景参考预算须在 I-1
冻结。实时数据只保留一个在途及一个最新待发目标，控制消息有序且不能被 latest
覆盖；溢出返回明确错误并按所有权恢复，不无限堆积。已有缓存仍为 20,000 帧／
1 GiB 及其原解析内存规则，不能用实时覆盖策略改变缓存顺序和完成语义。

## 保留给后续规格的扩展

- **多对象缓存：** 按集合冻结同一范围／fps／采样点，原子 Ready、原子应用，任何
  对象上传或修订失败使整组失效；随后修订 ADR 0013 的 segment／complete 语义。
  在这项实施前，多对象配置禁用捕获入口并说明原因；返回单角色后原缓存流程可用。
- **Sequencer 控制缓存：** 另定义外部时钟、抽样／插值、跳转和完成证据；不复用
  旧整段顺序播放的完成声明。首版镜头联动使用 Maya 实时求值。
- **更广宿主／内容：** 多于两个对象、多角色 Model preview、移动 socket、任意
  深层子序列、复杂 Nanite／Landscape／WP、MRQ 分辨率自动发现、跨机器、PIE、
  打包运行和自动重连不在首版承诺。DOF 始终区分参数一致与图像等价。

后续接手从 I-1 开始，在实施规格中固定推荐边界；有需求变化则先更新该规格。
原型及既有验收证据保留用于对照，正式路径联合验收完成后再单独决定其维护与退役。
