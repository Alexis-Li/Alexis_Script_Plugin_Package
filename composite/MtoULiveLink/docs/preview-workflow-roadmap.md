# MtoU 后续预览工作流

2026-09-22 用户确认的产品方向。本文描述待开发范围，不表示功能已实现。
当前基线为 `composite-mtou-livelink-v0.5.0`；后续开发分支为
`codex/mtou-preview-workflow`。下一版本号在实施时确定。

## 目标与顺序

MtoU 的目标是减少制作过程中在 Maya 与 UE 之间检查效果的阻力。
最终效果以 UE 为准，沿用现有 Maya 动画导出与 UE 导入、Sequencer 组装流程。

建议先完成界面整理与缓存操作分工，再做服装一键切换；相机、Sequencer、
场景参考模型、道具及多角色先验证可复用能力和空间／时间约定，再进入实施。
后几项是保留的候选方向，不是已经批准的完整技术方案。

## 已确认的近期范围

### 前端体验

- 按角色设置、预览方式、连接与操作组织界面；将低频诊断和高级设置折叠。
- 两端采用一致的术语与状态表达，清楚区分实时姿势、缓存、暂停与最后一帧。
- 状态说明给出可操作的下一步；不可用操作说明原因。
- 优化重复警告的呈现，保留差异和错误详情，避免相同内容反复打断操作。
- 不添加角色配置记忆、自动恢复或自动重连。

验收关注：用户无需查看诊断全文就能判断当前显示来源、连接状态和下一步操作。

### 缓存捕获与播放分工

Maya 负责捕获、捕获取消、上传及其进度／失败反馈。UE 负责缓存就绪后的
播放、循环、暂停、恢复和定位到指定帧。上传完成进入可播放状态；原有
“捕获并回放”入口需要随操作分工调整，不继续隐式承担 UE 播放控制。

Maya 增加“自定义捕获范围”开关与开始／结束帧：

- 开启：捕获输入区间，包含开始和结束帧。
- 关闭：捕获 Maya 当前播放范围（用户明确确认），不是场景完整动画范围。
- 捕获开始时固定区间与帧率；沿用现有帧数／体积限制，错误范围在捕获前提示。

UE 显示缓存范围、帧率、当前帧和状态；指定帧使用 Maya 源帧号，避免与
缓存数组下标混淆。只允许操作已完整接收并验证的缓存。用户主动暂停的等待
时间不应成为播放性能失败；定位、循环、自然结束和回到实时预览需分别定义。

此项会调整 [ADR 0013](adr/0013-upload-the-cache-before-local-replay.md) 中的
播放尝试与逐帧顺序完成语义。实施时更新协议、双方生命周期和验收，不把暂停、
跳帧定位或循环冒充旧协议中的一次顺序完整回放；完整上传、临时缓存和旧会话
消息隔离仍需保留。当前 ADR 在实施前继续描述现有行为。

### 原始服装／预览服装一键切换

UE 内切换原始 Driver 服装与 Generated Preview，保持相同角色姿势、Actor
位置、相机和光照。切换只改变比较显示，不等同于 Delete Preview、修改输入、
切换动画／模型工作流或重新生成；身体与 Additional Parts 保持正确显示。

实现前验证模型模式协商的 Morph 集合能否同时满足两个显示结果，不能仅隐藏
组件却让原始服装缺失当前应有的变形。输入发生变化仍沿用
[ADR 0002](adr/0002-end-streaming-when-preview-inputs-change.md) 的刷新／重连边界。
不做 UE 检查姿势、帧书签或问题区域可视化；检查动画由 Maya 提供。

## 保留并需验证的扩展

### UE 相机到 Maya，并研究 Sequencer 联动

方向固定为 UE → Maya，UE 镜头是权威来源。优先参考和复用官方 Live Link
相关能力，不从零实现已有链路，也不假定官方 Maya → UE 相机流可以直接反向。

需核对世界变换、焦距、视角、景深相关参数、焦点距离、光圈、画幅、裁切、
film fit／偏移、分辨率和分辨率门的映射。参数一致与渲染器景深观感一致需要
分别验证；不能用“焦距一致”替代最终构图一致，也不能预先承诺跨渲染器像素等价。

相机与 Sequencer 可作为同一镜头预览方向研究，但分为两项能力：镜头选择／
参数同步与时间同步。需要处理 Camera Cuts、子序列、帧率、起始帧及角色／道具
的空间偏移。确定每个模式的时间控制方，避免 Maya、UE 缓存播放器和 Sequencer
同时驱动；不要求初版做双向时间控制。镜头切换及烘焙效果以实际求值结果验收。

### UE 场景参考模型到 Maya

把 UE 所选关卡范围中的模型作为 Maya 动画制作参考，不导出贴图。
保留 UE 中组装后的世界位置、旋转、缩放及实例摆放；不把每个模型重置到原点。
若为精度或操作方便引入参考原点，相机、角色和道具必须使用同一个明确偏移。

实施前确定选择粒度（关卡／子关卡或选中 Actor）及支持对象；首轮建议验证
Static Mesh 与实例，单独确认 Blueprint 组件、Level Instance、Landscape 等
对象是否纳入。先评估现有导出能力；无贴图的参考几何传递不扩展为动画导入导出。

### 独立道具与多角色

制作事实：道具有独立 Maya 绑定文件，动画工程引用后与角色一起制作，但角色与
道具动画分别导出；UE 使用对应 Skeletal Mesh，在关卡 Sequencer 中组装。

候选方案是为每个独立动画对象建立明确 Maya 根节点 → UE Skeletal Mesh／目标
Actor 的配对，在同一预览时间下更新。道具优先复用 Maya 已求值的动画结果，
不复制约束或绑定系统。必须核对 Maya 引用层级与 UE Sequencer／挂点变换的
关系，避免重复应用父级运动或世界偏移；接管预览和退出预览均需恢复原有驱动。

多角色可与独立道具共享身份路由、配对和时间协调机制，但不提前建立通用平台。
女主完整身体与仅手臂网格骨架不同，应分别匹配对应 Maya 骨架／目标选项，
不是 Additional Parts，也不做重定向或假定两者可直接互换。

当前单角色单 Subject 的边界需要显式修订；验证两个不同骨架对象独立连接、
同步摆姿、缓存操作、断开清理和同名 Morph 隔离后，再扩大数量。

官方能力与待验证部分见 [技术调研](next-stage-research.md)。

## 本轮排除与暂缓

- 暂缓刷新响应／性能优化：当前等待时间可接受。
- 排除固定检查姿势、帧书签、问题区域可视化。
- 排除工作配置记忆与自动恢复。
- 排除录制为 UE 动画及新增动画导入导出流程。
- 排除自动重定向；骨架与绑定适配仍由绑定流程负责。
- 当前里程碑不制作安装包，也不新增宿主版本认证；本规划不扩展兼容性承诺。
