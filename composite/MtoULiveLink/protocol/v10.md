# MtoU Live Link protocol v10

Status: **frozen for the I-1 delivery (issue #57)**. This document owns the wire
contract that both host adapters implement; the executable form of the
regression and rejection cases is `conformance-v10.json` in this directory.

v10 keeps every v9 message, meaning and limit and adds the single-character
linkage workflow: an explicit target pairing, an exclusive time/camera control
state, complete pose groups with an application acknowledgement, and a
scene-reference handoff. v9 behaviour is not redefined; the corpus keeps the v9
cases as regression and adds the linkage, identity, resource and mixed-version
cases.

## Version pairing

- Both adapters declare `version: 10`. `MtoULiveLink.py` reports
  `PROTOCOL_VERSION = 10` and the Unreal plugin reports the same value.
- The Maya client opens with `hello`. A peer that cannot answer with the same
  version returns `error` with `code: "PROTOCOL_VERSION_MISMATCH"` and closes
  the connection **before** it discovers a target, borrows a camera, mutes a
  writer or reads a handoff directory. The same code answers a message whose
  `version` differs, including a v9 `init` against a v10 adapter.
- A mismatched pair never partially succeeds: no partial target takeover, no
  half-imported reference, no cached pose left behind.

## Framing and limits

| Limit | Value | Enforced where |
| --- | --- | --- |
| `max_message_bytes` | 33,554,432 (32 MiB) | both adapters before any JSON parse or allocation; a longer frame closes the connection |
| `max_linkage_group_bytes` | 33,554,432 (32 MiB) measured over the **whole** group message, not per object | Unreal rejects an oversized group with `RESOURCE_LIMIT` and keeps the last complete display |
| `max_control_queue` | 16 undelivered control messages per direction | both adapters; overflow is an error, never an unbounded backlog |
| `max_pending_camera_targets` | 1 in flight + 1 replaceable pending | Unreal scheduler |
| `max_reference_bytes` | 268,435,456 (256 MiB) | Maya importer before staging |
| `max_reference_objects` | 20,000 imported roots | Maya importer before staging |
| `max_reference_triangles` | 20,000,000 | Maya importer before staging |
| cache contract | unchanged v9: 20,000 frames / 1 GiB | both adapters |

The numbers above are the frozen I-1 budgets; they were fixed before the
acceptance runs and the measured values are reported next to them. A budget is
changed only with a recorded reason, never to make a failing run pass.

## Roles and authority

- **Maya** owns the character scene, the evaluated pose sample and its own
  timeline. It never commands Unreal time or camera.
- **Unreal** owns the target, its writers, the Level Sequence time, the
  evaluated camera and the output gate. It never edits Maya scene data.
- Exactly one host controls time in each mode. `mode` is the authority
  statement; both adapters display it and refuse work that contradicts it.

## Identity

| Field | Owner | Meaning |
| --- | --- | --- |
| `session_id` | Unreal | positive integer for one TCP connection; every later message repeats it |
| `set_revision` | Maya | increments per accepted object set; I-1 has exactly one object (`object_id: "character"`) |
| `mode_revision` | Unreal | increments per accepted mode transition |
| `space_revision` | Unreal | binds the common anchor, unit and mapping; a reference and a frame group must match the current one |
| `object_id` | both | stable object identifier, never a display name, bone short name or list position |
| `eval_id` | Unreal | opaque evaluation identity: time plus cut plus camera content, at 1/1000 tick precision |
| `transport_serial` | Unreal | monotonically increasing send counter; ordering only |
| `sample_serial` | Maya | increments per new sample of one `eval_id`; a paused edit produces a new sample |
| `frame_serial` | Unreal | counts publications of one connection, including heartbeats |

A message naming an old session, set, space, mode, cancelled target or repeated
publication is refused with its specific code and changes no host state.

## Messages: Maya → Unreal

v9 messages (`init`, `frame`, `cache_enter`, `cache_begin`, `cache_frame`,
`cache_end`, `cache_play`, `cache_stop`, `cache_clear`) keep their v9 fields and
meaning. v10 adds:

| `type` | Payload | Notes |
| --- | --- | --- |
| `hello` | `version`, `host`, `maya_version`, `scene{linear_unit, unit_scale_cm, fps}`, `capabilities{linkage, reference, cache, model}` | first message of a connection |
| `init` | v9 fields plus `object_id`, `set_revision`, `space_revision` | one per object; negotiates without a linkage pairing (the v9 workflows need none); an existing pairing must name the placed Binding actor |
| `mode` | `session_id`, `mode_revision`, `mode`, `control`, `transition`, `detail` | Maya's authority statement after a transition; `transition` is `ready` or `failed` |
| `group` | `session_id`, `set_revision`, `mode_revision`, `space_revision`, `eval_id`, `transport_serial`, `sample_serial`, `objects[{object_id, transforms, curves}]`, `camera{...}`, `time{maya_frame, ue_display_frame}` | one complete sample answering one `camera_time` target |
| `leave_linkage` | `session_id`, `mode_revision`, `target` (`realtime` or `end`), `detail` | Maya confirms it restored its own state |
| `reference_result` | `session_id`, `transfer_id`, `accepted`, `detail`, `counts{objects, triangles, bytes}`, `container` | outcome of a local handoff import, swap or removal |
| `reference_removed` | `session_id`, `detail` | the user removed the tool-owned container |

`group.objects` carries one row per object of the current set, each with the
complete bone transform list and Morph value list the object negotiated. A
partial set is never sent.

## Messages: Unreal → Maya

v9 messages (`ready`, `error`, `cache_ready`, `cache_playing`, `cache_progress`,
`cache_complete`, `cache_paused`, `cache_resumed`, `cache_seeked`,
`cache_looped`, `cache_loop_changed`, `cache_stopped`, `cache_cleared`) keep
their v9 fields and meaning. v10 adds:

| `type` | Payload | Notes |
| --- | --- | --- |
| `hello_ack` | `version`, `session_id`, `capabilities`, `target{object_id, kind, binding_path, generation}`, `space{space_revision, anchor}` | `target` describes the explicitly selected target; empty until the user pairs |
| `ready` | v9 fields plus `session_id`, `object_id`, `set_revision`, `space_revision` | negotiation result for one object |
| `camera_time` | `session_id`, `set_revision`, `mode_revision`, `space_revision`, `eval_id`, `eval_serial`, `transport_serial`, `frame_serial`, `time{display_frame, source_frame, seconds, tick, display_rate{n,d}, tick_resolution{n,d}, playback_range{start,end}}`, `camera{...}`, `gate{...}`, `cut{stage, name}` | the current linkage target; heartbeats repeat an unchanged target |
| `applied` | `session_id`, `mode_revision`, `eval_id`, `sample_serial`, `applied`, `applied_display_frame`, `lag_seconds`, `components[{object_id, bones, morphs, parts}]`, `reason` | actual component completion evidence: sent only once the Live Link subject holds that group's publication and every display component (primary and each enabled part) evaluated its bones and Morph values; `false` with the reason when that does not happen within 2 s. One group is published at a time |
| `mode_state` | `session_id`, `mode_revision`, `mode`, `control`, `detail` | Unreal's authority statement |
| `reference_offer` | `session_id`, `transfer_id`, `directory`, `manifest_digest`, `scope{level, sublevels, completeness, unloaded_sublevels}`, `space_revision`, `counts{objects, triangles, bytes}` | a finished local handoff the user may import |
| `reference_query` | `session_id`, `transfer_id`, `scope` | reserved: Maya may ask for a handoff of a scope; I-1 ships the one-way flow (Unreal exports and offers) and does not use this message |

## Mode transitions

| From | To | Preconditions | Failure and recovery |
| --- | --- | --- | --- |
| realtime | linkage | target paired and writer-isolatable; Maya has no cached playback active; either host may start it | Maya keeps realtime, Unreal restores nothing; both report the code (see "Starting and ending from either host") |
| cached | linkage | the user cleared the cache and Maya saw the matching `cache_cleared` | no new mode; the old cache is never revived |
| linkage | realtime | linkage active | Maya restores time/view/gate and stays paused; Unreal keeps its takeover; a failed restore ends the session and reports the residual |
| linkage | end | linkage active or already left | every borrowed resource is restored per resource, idempotently; the original writer returns; an exit that already happened is confirmed with `mode_state`, not refused |
| linkage | realtime | the takeover's Level Sequence was closed or switched, its world closed or the paired target destroyed | Unreal restores the writers, drops the last synchronisation and sends `mode_state` realtime at a new revision with `TARGET_UNKNOWN`; Maya restores itself |
| any | disconnected | socket loss | gate first, then restore; no automatic reconnect |

### Starting and ending from either host

- Unreal starts: it takes the target over, sends `mode_state` linkage at the new
  revision N and keeps the pose gate closed until Maya answers `mode` linkage N
  `ready`. Maya refuses with `mode` realtime N `failed` and Unreal restores its
  writers at once; without an answer Unreal fails the transition after 5 s.
- Maya starts: its `mode` linkage revision must be newer than every revision of
  the connection. Unreal confirms with `mode_state` linkage N; a refusal is a
  `mode_state` realtime at Unreal's current revision, and Maya restores itself
  and adopts that revision. Without a confirmation within 5 s Maya restores
  itself and sends `mode` realtime N `failed`.
- Unreal leaves: `mode_state` realtime at a newer revision. Maya restores its
  time, view and gate, stays paused and does not answer with `leave_linkage`.

`mode_revision` increments on every accepted transition and is echoed by both
sides. During a transition the pose gate is closed: no `group` and no `applied`
is accepted for the previous revision.

## Time mapping

```
maya_time = maya_origin + (ue_display_frame - playback_range.start)
            * maya_fps / display_rate
```

`display_rate` is a rational (`numerator`/`denominator`); frames are never
rounded to integers. `ue_display_frame` is always the root Level Sequence's
time; a subsequence contributes no second offset. `maya_origin` is captured when
linkage starts, so returning to realtime restores the frame the artist had.

## Space

- Common space: centimetres, `C(x, y, z) = (x, z, y)` from Maya to Unreal, with
  one static anchor `A` (translation and rotation, unit scale). `A = identity`
  is the original workflow.
- Camera and reference geometry travel back through the inverse mapping; the
  camera basis is transferred as basis vectors, never as Euler angles.
- `space_revision` changes when `A`, the unit or the mapping changes. A
  reference or an in-flight group from an older revision is refused
  (`SPACE_REVISION_STALE`); re-labelling an old reference is not an update.

## Scheduling (Unreal side)

- `desired` is the newest target the editor wants displayed, `issued` is the
  target Maya is answering, `applied` is the last group whose components were
  read back on the game thread.
- At most one `issued` and one replaceable `desired`. Continuous playback
  replaces only the pending target; an advancing `desired` never cancels an
  `issued` target. Pause, cut, camera edit and explicit discontinuity (a jump or
  scrub, also within one shot, and a loop wrap) cancel the issued and the waiting
  target and issue the new one at once; the editor marks such a target as
  discontinuous when the sequence is not playing or its time stepped backwards
  or more than half a second ahead. The
  old target; an ordinary camera move along continuous time does not.
- A `group` whose `eval_id` is no longer current is refused with `EVAL_STALE`
  and changes nothing; the last complete display stays.
- After the last desired target, Unreal must observe an applied group within
  2 s and only then report 已同步; otherwise it reports 未收敛 with the last
  target and the elapsed time.

## Rejection codes

Codes are stable; the message text is diagnostic only.

| Code | Trigger |
| --- | --- |
| `PROTOCOL_VERSION_MISMATCH` | version field or `hello` version differs |
| `INVALID_MESSAGE` | malformed shape, non-finite number, wrong length, duplicate id |
| `PAIRING_REQUIRED` | linkage requested (Unreal entry or Maya `mode`) for an object the user has not paired |
| `TARGET_UNKNOWN` | paired target no longer resolves (destroyed, level unloaded) |
| `TARGET_ALREADY_PAIRED` | a second object claims one target |
| `WRITER_NOT_ISOLATABLE` | the target's writers cannot be muted without touching unrelated tracks |
| `SHARED_WRITER` | a writer drives the target and another object |
| `MOVING_SOCKET` | the target is parented to a moving socket |
| `MODE_CONFLICT` | the requested transition contradicts the current mode or revision |
| `CACHE_NOT_CLEARED` | linkage requested while a cache is still owned |
| `SET_REVISION_STALE` | message names an older object set |
| `SPACE_REVISION_STALE` | message names an older common space |
| `EVAL_STALE` | group answers a cancelled or superseded target |
| `RESOURCE_LIMIT` | message or group exceeds a frozen budget |
| `REFERENCE_STALE` | the offered manifest belongs to an older space revision |
| `REFERENCE_DIGEST_MISMATCH` | the directory content does not match the offered digest |
| `REFERENCE_IMAGE_DATA` | the handoff delivers image data |
| `REFERENCE_OVER_BUDGET` | file, object or triangle budget exceeded |
| `CONTAINER_NOT_OWNED` | a node under the container name lacks the ownership mark |
| `RECOVERY_REFUSED` | a previous reference or writer state cannot be restored safely |
| `LINKAGE_NOT_ACTIVE` | a linkage-only message arrived in another mode |

## Corpus

`conformance-v10.json` is language-neutral and executed by both adapters'
test suites. It keeps the v9 cases as regression and adds:

- identity: set/space/mode staleness, repeated publication, a repeated sample
  serial and a group that names another session (the cancelled-target and
  paused-resample refusals are pinned by the linkage unit tests on both ends,
  not by a corpus case);
- linkage: `hello`/`hello_ack` pairing, mode transitions and their failures,
  camera/time application, complete group results, applied evidence;
- resources: oversized group, over-budget reference, control-queue overflow;
- mixed version: a v9 `init`, `frame` and `cache_begin` against a v10 adapter;
- reference: digest mismatch, image data, foreign container node, stale
  revision, removal.
